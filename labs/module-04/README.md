# Module 4 labs — Wireless reconnaissance

Module 4 is recon. Its labs are **recon-lite**: discovery is largely passive reception, with at most a
single directed probe at an SSID **you own**. Every active step is owned-equipment-only, at minimum
transmission, and restated with a warning in the lesson. Most of the module can be completed on the
**recorded-data (R)** path with no hardware; **virtual (V)** and **physical (P)** paths add live
discovery for those who built them.

## In this module's zip

- This README.
- `captures/` — the supplied captures and datasets the lessons read (provenance table below).
- `hostapd-recon.conf` — a minimal `hostapd` config for a lab BSS (`LAB-RECON`), including a hidden-SSID
  BSS, for the V/P discovery labs (04.1, 04.2).
- `client-saved-networks.conf` — a `wpa_supplicant` config giving a controlled lab client two synthetic
  saved networks (`LAB-HOME`, `LAB-CAFE`) for the probe-request/PNL lab (04.3).
- From `labs/common/`: `hwsim-up.sh`, `hwsim-down.sh` (bring the `mac80211_hwsim` radios up/down),
  `setup-check.sh`, and `reset-lab.sh`.

## Supplied captures and datasets — provenance

Every shipped capture/dataset records how it was generated, its licence, its SHA-256, and what it
should show. All are **generated by the scripts in `labs/common/` on owned or simulated equipment with
synthetic credentials**, and checksums are recorded **at generation time** — never invented. Until a
file has been generated and verified on a real build, its checksum is marked `VERIFY`. The wardrive
dataset is **synthetic** (fabricated coordinates and names) and contains **no real personal data**.

| File | How generated | Shows | Licence | SHA-256 |
|---|---|---|---|---|
| `captures/discovery-passive.pcapng` | lab script, simulated/owned radios | a passive pass: beacons + others' probes, no self-sent probes | course lab, redistributable | VERIFY |
| `captures/discovery-active.pcapng` | lab script, simulated/owned radios | an active pass: self-sent directed probes + the probe responses | course lab, redistributable | VERIFY |
| `captures/airodump-survey.txt` | saved airodump-ng screen, lab run | an AP/stations table incl. a hidden-SSID row and a not-associated client | course lab, redistributable | VERIFY |
| `captures/survey.pcapng` | lab script, owned AP + client | the frames behind the survey, incl. the association revealing the hidden SSID | course lab, redistributable | VERIFY |
| `captures/probe-requests.pcapng` | lab script, controlled clients | one stable-MAC client exposing a PNL vs one randomised/broadcast client | course lab, redistributable | VERIFY |

> [!NOTE]
> Captures contain only synthetic SSIDs (`LAB-RECON`, `LAB-HOME`, `LAB-CAFE`) and no real user traffic
> or payloads. Confirm each file parses, matches its recorded checksum, and produces the claimed result

## Virtual / physical discovery labs (04.1, 04.2)

Outline (pin exact versions in your own notes per `TOOLS.md`):

```bash
sudo ./labs/common/hwsim-up.sh                 # (V) load mac80211_hwsim -> wlan0, wlan1
sudo hostapd hostapd-recon.conf                # bring up LAB-RECON (+ a hidden-SSID BSS)
sudo airodump-ng wlan0mon                      # hopping survey: find LAB-RECON, its channel + security
sudo airodump-ng --channel <ch> --bssid <bssid> -w lab-01 wlan0mon   # lock + capture one BSSID
sudo kismet -c wlan0mon                         # passive sensor: compare AP + client/PNL view
sudo ./labs/common/hwsim-down.sh               # (V) cleanup: remove simulated radios
```

- **Start state:** path built and verified (`lessons/module-03/`); `LAB-RECON` beaconing on a known
  channel with one controlled client; target allowlist written (`lessons/module-00/lesson-03.md`).
- **Expected artifacts:** an annotated AP table naming each network's real security; a channel-locked
  capture `lab-01*.pcapng` of your own BSSID; a Kismet screenshot/export of the same AP and its clients.
- **Success criteria:** you identify your own AP from beacons alone (passive), lock and capture its
  frames, and read the client/PNL view — all without transmitting at any network you do not own.
- **Troubleshooting:** empty capture while target is in the survey → you are hopping, add `--channel`;
  AP missing → wrong band/channel; `PWR` shows `-1` → driver does not report signal (expected on some
  adapters and on V); Kismet UI not loading → confirm the monitor source and that monitor mode is up.
- **Cleanup:** stop `airodump-ng`/`kismet`; on V run `hwsim-down.sh`; delete capture files you do not
  keep, or record provenance for ones you do. On P, log any directed probe you sent to your own AP.

## Probe-request / PNL lab (04.3)

- Configure a **controlled** lab client with the synthetic saved networks in
  `client-saved-networks.conf` (or add them on an owned phone/laptop), capture its scanning with
  `airodump-ng`/Kismet, then toggle MAC randomisation and recapture.
- **Expected artifacts:** the directed SSIDs your own client exposed; a before/after randomisation note
  with the tested OS/version; a one-line conditional evil-twin judgement for one of those SSIDs.
- **Privacy cleanup:** delete captured probe data (it concerns real devices even when they are yours)
  and remove the synthetic saved networks from the client afterwards.

## Cleanup (whole module)

Recorded-data lessons transmit and capture nothing — no cleanup. Live labs are reset by `hwsim-down.sh`
(V) and by stopping services and clearing capture/probe files (P); `reset-lab.sh` is the catch-all.
Nothing in this module should leave a rogue AP, a saved synthetic network, or captured probe data in
place after the session.
