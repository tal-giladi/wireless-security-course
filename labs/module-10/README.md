# Module 10 labs — Enterprise I: architecture, EAP & building the lab

Module 10 is the **build half** of the enterprise sequence: you learn the 802.1X roles and the EAP
methods, then stand up a working enterprise network — a local CA, FreeRADIUS, hostapd as the
authenticator, and a validating wpa_supplicant client. There is **no attack in this module**; the
intentionally-insecure client and the rogue-RADIUS attack live in Module 11, which reuses everything you
build here. Lessons 10.1 and 10.2 are recorded-data analysis (R); lesson 10.3 is a virtual build (V),
with physical (P) as an optional swap of the simulated radios for a real adapter in AP mode.

## Virtual (V) build lab — lesson 10.3

Stand up a working enterprise network with no hardware and no transmission (full steps and config
outlines in [`../../lessons/module-10/lesson-03.md`](../../lessons/module-10/lesson-03.md)):

```bash
sudo ./labs/common/hwsim-up.sh 2            # mac80211_hwsim -> wlan0 (AP), wlan1 (client)
# in certs/: generate the CA + server cert (replaces the snake-oil certs)
# point mods-available/eap at server.pem/.key and ca.pem; add the AP to clients.conf; add the test user
sudo freeradius -X                           # server, foreground debug: watch for "Login OK"
sudo hostapd -dd /tmp/lab-ent-ap.conf        # authenticator (ieee8021x=1, auth_server_* -> 127.0.0.1)
sudo wpa_supplicant -i wlan1 -c /tmp/lab-client-peap.conf -d   # validating PEAP client
iw dev wlan1 link                            # expect "Connected to <BSSID>" on LAB-ENTERPRISE
sudo ./labs/common/hwsim-down.sh ; sudo ./labs/common/reset-lab.sh   # cleanup
```

- **Start state:** a Linux VM with `mac80211_hwsim`, `freeradius`, `hostapd`, `wpa_supplicant`, `iw`
  installed; no CA, server, or client profile yet; nothing transmitted over the air.
- **Expected artifacts:** the issued `ca.pem` and `server.pem`; the FreeRADIUS `-X` log line showing
  `Login OK` / `Access-Accept` for `labuser@lab.local`; the `wpa_supplicant` log showing certificate
  validation, `EAP-SUCCESS`, and `CTRL-EVENT-CONNECTED`; the `client-peap.conf` profile; the
  `iw dev wlan1 link` line on `LAB-ENTERPRISE`.
- **Success criteria:** a client authenticates via EAP (PEAP/MSCHAPv2) and reaches the connected state,
  and you can point to the accept in the RADIUS log. This is the known-good baseline for Module 11.
- **Troubleshooting:** certificate error at FreeRADIUS startup (CA/server cert not generated, or `eap`
  module paths wrong); `Access-Reject` "unknown client" (the AP's `clients.conf` `ipaddr`/`secret` do not
  match hostapd's `auth_server_*`); client stuck at EAP (`ca_cert` unreadable or `domain_suffix_match`
  does not match the server cert name); hostapd exits immediately (radio busy — run `reset-lab.sh`);
  distro path differences (`/etc/freeradius/3.0/` vs `/etc/raddb/`).
- **Cleanup:** stop the three daemons, run `hwsim-down.sh` then `reset-lab.sh`. Delete the synthetic
  CA/keys and client profile if not reused. Nothing was transmitted — no RF cleanup.

> [!NOTE]
> **LAB TARGET vs REAL NETWORK:** `LAB-ENTERPRISE` exists only inside the simulated radios and radiates
> nothing. The CA, server certificate, identity, and password are synthetic and local. Never point a
> client profile holding real credentials at any network you do not own.

## Physical (P) option — lesson 10.3

The P path is optional and changes only the radios: run `hostapd` on a real adapter in **AP mode** (verify
AP-mode support per [`../../curriculum/lab-matrix.md`](../../curriculum/lab-matrix.md) — it is a separate
capability from monitor/injection) and connect a real client. The CA, FreeRADIUS, and profile steps are
identical.

> [!WARNING]
> AP mode transmits **real radio in range**. Owned equipment only, on your allowlist, at minimum TX power,
> on a chosen channel, with stop conditions and cleanup
> ([`../../lessons/module-00/lesson-03.md`](../../lessons/module-00/lesson-03.md)). A private subnet does
> not contain radio. Prefer the virtual path for anything that does not strictly need real RF.

## Cleanup (whole module)

Recorded-data analysis (10.1, 10.2) transmits nothing. The virtual build (10.3) is reset by
`hwsim-down.sh` plus `reset-lab.sh`, which is the catch-all for any state left behind; stop `freeradius`,
`hostapd`, and `wpa_supplicant` first. Remove synthetic CA/keys and client profiles you will not reuse.
