# Module 1 labs — RF & 802.11 fundamentals

Module 1 is foundations. There are **no attack labs** here: every exercise is either **recorded-data
analysis** (read supplied captures and radiotap metadata) or, for lesson 01.4, a **virtual** join you
observe on simulated radios. Nothing in this module transmits over the air.

## In this module's zip

- This README.
- `captures/` — the supplied captures the lessons dissect (see the provenance table below).
- `hostapd-open.conf`, `join.conf` — minimal configs for the lesson 01.4 virtual (V) join lab.
- From `labs/common/`: `hwsim-up.sh`, `hwsim-down.sh` (bring the `mac80211_hwsim` radios up/down),
  `setup-check.sh`, and `reset-lab.sh`.

## Supplied captures — provenance

Every shipped capture records how it was generated, its licence, its SHA-256, and what it should show.
Captures are **generated by the scripts in `labs/common/` on owned, simulated or lab equipment with
synthetic credentials**, and their checksums are recorded **at generation time** — never invented.
Until a capture has been generated and verified on a real build, its checksum is marked `VERIFY`.

| File | How generated | Shows | Licence | SHA-256 |
|---|---|---|---|---|
| `captures/beacon-sample.pcapng` | lab generation script, simulated/owned AP | beacons with readable radiotap signal + channel | course lab, redistributable | VERIFY |
| `captures/multi-channel-beacons.pcapng` | lab generation script, owned APs on several channels | networks across 2.4/5 GHz with varied width | course lab, redistributable | VERIFY |
| `captures/frame-types-sample.pcapng` | lab generation script, owned AP + client | one of each type: management, control, data | course lab, redistributable | VERIFY |
| `captures/join-sequence.pcapng` | lab generation script, owned AP + client | full discovery → auth → association → EAPOL | course lab, redistributable | VERIFY |

> [!NOTE]
> These captures contain only synthetic SSIDs (e.g. `LAB-JOIN`) and no real user traffic. Confirm each

> version before relying on it (release-check list, course `CLAUDE.md`).

## Virtual (V) join lab — lesson 01.4

The virtual path reproduces a real join with no hardware and no transmission. Outline (pin exact
versions in your own notes per `TOOLS.md`):

```bash
sudo ./labs/common/hwsim-up.sh            # load mac80211_hwsim -> wlan0, wlan1
sudo hostapd hostapd-open.conf            # OPEN lab BSS on wlan0 (SSID: LAB-JOIN)
sudo wpa_supplicant -i wlan1 -c join.conf -d   # client joins; watch auth then assoc in the log
iw dev wlan1 link                         # expect "Connected to <BSSID>"
sudo ./labs/common/hwsim-down.sh          # cleanup: remove simulated radios
```

- **Start state:** Linux VM; `mac80211_hwsim`, `hostapd`, `wpa_supplicant`, `iw` installed.
- **Expected artifacts:** `hostapd` / `wpa_supplicant` logs showing authentication then association, and
  the `iw dev wlan1 link` line confirming association to the simulated BSSID.
- **Success criteria:** the client reaches the associated state; you can point to the auth and assoc
  frames/log lines in order and explain that no key was exchanged until (on a secured BSS) the handshake.
- **Troubleshooting:** module not loaded (`modprobe mac80211_hwsim`); interface names differ
  (`iw dev` to list); `hostapd` fails to start (check the conf path and that the radio is free);
  `wpa_supplicant` can't find the BSS (confirm both interfaces share the simulated phy and channel).
- **Cleanup:** stop `hostapd`/`wpa_supplicant`, run `hwsim-down.sh`. Nothing was transmitted, so there
  is no RF cleanup.

## Cleanup (whole module)

Recorded-data lessons transmit and capture nothing — no cleanup. The virtual lab is reset by
`hwsim-down.sh` (and `reset-lab.sh` as a catch-all).
