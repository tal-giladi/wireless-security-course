# Module 11 labs — Enterprise II: attack, harden & retest

Module 11 is the **attack-and-defend half** of the enterprise sequence. It reuses the known-good network
you built in Module 10 (local CA + FreeRADIUS + hostapd + wpa_supplicant) and does four things to it:
stands a **rogue RADIUS server** in front of a non-validating client to **capture** an MSCHAPv2 exchange
(11.1), **cracks** that exchange bounded and strong (11.2, recorded path), distinguishes offline
**capture from live relay** (11.3), **hardens** the client with a pinned private CA, an expected server
name, and EAP-TLS (11.4), and **proves** the hardened client **rejects** the rogue server with log and
packet evidence (11.5). Lessons 11.1, 11.3, 11.4, 11.5 are virtual builds (V, path P optional); lesson
11.2 is recorded-data analysis (R).

> [!WARNING]
> Every attack here runs **only** against the owned Module 10 lab, with the synthetic identity
> `labuser@lab.local` and synthetic credentials, on simulated radios (V) or an isolated owned rig (P). A
> rogue RADIUS server impersonates a real authentication server; aimed at any network you do not own it
> harvests real users' credentials — interception, and over the air interference
> ([`../../lessons/module-00/lesson-03.md`](../../lessons/module-00/lesson-03.md)). A private subnet does
> not contain radio. Prefer the virtual path.

## Paths supported in this module

| Lesson | Path(s) | What the lab proves | What it does NOT prove |
|---|---|---|---|
| 11.1 credential capture | V (P optional) | standing a rogue RADIUS server and capturing an MSCHAPv2 exchange from a non-validating client; that a validating client refuses | real RF, drivers, range, interference, hardware AP/monitor quirks |
| 11.2 cracking MSCHAPv2 | R | recovering the bounded password and reaching the correct no-crack conclusion for the strong one | live capture, injection, RF |
| 11.3 relay vs capture | V | classifying capture vs relay by preconditions and evidence; optionally looping a relay between **owned** endpoints | cross-network/over-the-air relay (out of scope), real RF |
| 11.4 hardening | V (P optional) | configuring CA + name pinning and EAP-TLS and measuring that the rogue server captures nothing | real RF, hardware quirks |
| 11.5 client rejects rogue | V (P optional) | the hardened client rejecting the rogue server, with log + packet evidence and the reason | real RF, hardware quirks |

**R and V never grant physical-capture or injection credit**
([`../../curriculum/assessment-rubrics.md`](../../curriculum/assessment-rubrics.md)). On path P the rogue
server and AP mode transmit **real radio in range** — owned equipment, allowlist, minimum TX, stop
conditions, cleanup.

## Virtual (V) labs — lessons 11.1, 11.3, 11.4, 11.5

All reuse the Module 10 build and transmit nothing (full steps and config in the lessons). Stop the real
10.3 FreeRADIUS/hostapd first so the rogue server owns the SSID:

```bash
sudo ./labs/common/reset-lab.sh
sudo ./labs/common/hwsim-up.sh 2                 # wlan0 (rogue AP), wlan1 (client)
sudo hostapd-wpe /etc/hostapd-wpe/hostapd-wpe.conf   # ssid=LAB-ENTERPRISE; or eaphammer --essid LAB-ENTERPRISE --creds
# 11.1 capture:  sudo wpa_supplicant -i wlan1 -c ./labs/module-11/client-peap-insecure.conf -d   # LEAKS an MSCHAPv2 exchange
# 11.5 reject:   sudo wpa_supplicant -i wlan1 -c ./labs/module-11/client-peap-hardened.conf -d   # REFUSES in phase 1, logs the reason
sudo ./labs/common/hwsim-down.sh ; sudo ./labs/common/reset-lab.sh    # cleanup
```

- **Start state:** the Module 10 enterprise lab built and working
  ([`../../lessons/module-10/lesson-03.md`](../../lessons/module-10/lesson-03.md)) with its CA
  (`lab-ca.pem`) and server certificate; the real 10.3 services **stopped**; `hostapd-wpe`/`eaphammer`
  installed; nothing transmitted over the air.
- **Expected artifacts:** (11.1) the rogue server's log capturing an MSCHAPv2 challenge/response for
  `labuser@lab.local` in a crackable format, plus a log showing the validating client send nothing; (11.4)
  the before/after rogue logs (captured vs empty) and the hardened profile; (11.5) the
  `CTRL-EVENT-EAP-TLS-CERT-ERROR` + `EAP-FAILURE` client log with **no** `EAP-SUCCESS`, an empty rogue
  capture, and a `rogue-reject.pcapng` trace showing the server `Certificate` then the client `Alert`.
- **Success criteria:** 11.1 — capture the exchange from the insecure client **and** show the validating
  client sends nothing. 11.4 — the rogue server captures a credential from the vulnerable client and
  **captures nothing** from the hardened client. **11.5 — the correctly-configured client rejects the rogue
  server and you can show the reason; demonstrating this rejection is a full pass, no attack needs to
  succeed.**
- **Troubleshooting:** rogue server won't start (real 10.3 services still hold the radio — `reset-lab.sh`);
  client joins the wrong SSID (rogue `ssid` must match the profile); hardened client "fails" to leak (that
  is the **correct** result); no `CERT-ERROR` line (raise `wpa_supplicant` debug with `-d`/`-dd`); EAP-TLS
  client has nothing to capture by design; tool flag/config path differs (check the installed version's
  `--help`/wiki).
- **Cleanup:** Ctrl-C the rogue server, any real FreeRADIUS, and `wpa_supplicant`; `hwsim-down.sh` then
  `reset-lab.sh` (the catch-all). Delete synthetic captures/keys/profiles you will not reuse; keep the
  11.5 refusal evidence as a retest artifact. Nothing transmitted on V.

## Recorded (R) lab — lesson 11.2

No hardware, no transmission (full steps in
[`../../lessons/module-11/lesson-02.md`](../../lessons/module-11/lesson-02.md)):

```bash
./labs/common/make-wordlists.sh                                  # bounded.txt, strong-absent.txt
hashcat -m 5500 hash.5500 ./wordlists/bounded.txt                # recovers Lab-WiFi-Passw0rd!
hashcat -m 5500 hash-strong.5500 ./wordlists/strong-absent.txt   # Exhausted (correct no-crack)
asleap -C <server-challenge> -R <response> -W ./wordlists/bounded.txt   # dedicated alternative
```

- **Success criteria:** recover the bounded password **and** correctly conclude the strong password will
  not crack in scope (back it with a keyspace/hashrate estimate and a control recommendation).
  **Correctly failing to crack the strong case is a full pass.**
- **Cleanup:** nothing transmits; remove scratch hashlines/potfiles, never commit a recovered real
  password. `reset-lab.sh` is for the live labs, not this one.

## Physical (P) option — lessons 11.1, 11.4, 11.5

The P path changes only the radios: run the rogue server and `hostapd` on a real adapter in **AP mode**
(verify AP-mode support per [`../../curriculum/lab-matrix.md`](../../curriculum/lab-matrix.md)) and connect
a real client. The CA/RADIUS/profile/EAP-TLS steps are identical.

> [!WARNING]
> A rogue RADIUS server and AP mode transmit **real radio in range**. Owned equipment only, on your
> allowlist, at minimum TX power, on a chosen channel, with stop conditions and cleanup
> ([`../../lessons/module-00/lesson-03.md`](../../lessons/module-00/lesson-03.md)). Never run the rogue
> server against a real network, even to "prove the fix." Prefer the virtual path.

## Cleanup (whole module)

Recorded-data cracking (11.2) transmits nothing. The virtual labs (11.1, 11.3, 11.4, 11.5) are reset by
`hwsim-down.sh` plus `reset-lab.sh` (the catch-all for any state left behind); stop the rogue server, any
`freeradius`, `hostapd`/`hostapd-wpe`/`eaphammer`, and `wpa_supplicant` first. Remove synthetic CA/keys,
captured exchanges, and client profiles you will not reuse; keep the 11.5 rejection evidence if you want
it as a retest artifact.

> **LAB TARGET vs REAL NETWORK:** every SSID, CA, certificate, identity, and password in this module is
